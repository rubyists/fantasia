= ADR 0001: Phase 0 compatibility and provenance
:status: accepted
:date: 2026-09-14

== Context

Fantasia replaces behavior from a moving Python implementation. Textual version declarations are
insufficient evidence because parent mise configuration can place an unrelated executable first on
`PATH`.

== Decision

The machine-readable ledger at
`apps/stokowski/test/fixtures/compatibility_ledger.yaml` is the normative Phase 0 index. Every row
names a source commit or executable version, an immutable fixture, observable input and output, a
`preserve`, `correct`, or `defer` disposition, and an owning ADR. Tests reject incomplete rows,
duplicate identifiers, unknown dispositions, invalid provenance, and missing fixtures or ADRs.

The historical compatibility evidence baseline is `vendor/stokowski@b80db05`,
`vendor/Continuum@237dfbb`, and `codex-cli@0.154.0`. Fantasia now pins Stokowski `26c3cff`, which
descends from the environment-containment correction at `342862a` and adds the unified effort and
session-continuity contracts recorded in ADR 0003. Ledger rows cite the exact source revision that
owns their behavior; preserved historical behavior may continue to cite `b80db05`. Codex is
resolved by asking mise for the checkout-selected executable, probing that absolute path, and
comparing the observed version with `mise.toml`. The verified directory is prepended for the Python
child. Startup reports only the executable path and version.

== Consequences

Fixture changes require an explicit ledger decision. Ambient `PATH` order cannot silently replace
Codex. Updating Codex requires updating the pin, provenance fixture, and capability evidence in one
change.
