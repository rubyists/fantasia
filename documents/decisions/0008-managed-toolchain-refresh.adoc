= ADR 0008: Managed toolchain refresh and historical runner evidence
:status: accepted
:date: 2026-09-18

== Context

https://github.com/rubyists/fantasia/pull/14[PR 14] updates the six tools installed through the
root `mise.toml`. The runner fixtures and compatibility ledger still identify the executables
used for the Phase 0 evidence: `codex-cli@0.154.0` and Claude Code `2.1.270`.

link:0001-phase-0-compatibility-and-provenance.adoc[ADR 0001] requires a Codex update to change
the pin, provenance fixture, and capability evidence together. Changing a fixture's version
without capturing new observations would misstate its provenance. This decision explicitly
accepts the new installation pins while retaining the historical evidence and its contracts.

== Decision

=== Accepted toolchain

The root `mise.toml` is authoritative for the tools installed and selected in this checkout.
Accept the following refresh:

[cols="1,1,1",options="header"]
|===
|Tool |Previous pin |Accepted pin

|Erlang/OTP |29.0.3 |29.1
|Elixir |1.20.3 |1.20.4
|Python |3.14.1 |3.14.7
|uv |0.12.0 |0.12.16
|Codex |0.154.0 |0.155.1
|Claude Code |2.1.270 |2.1.276
|===

This table supersedes the tool versions proposed in the
link:../plans/pre-phase-1-plan.adoc[Pre-Phase 1 bootstrap plan]. That plan remains a historical
proposal; its version example is not an installation manifest.

=== Historical evidence and current executable identity

For the Codex `0.154.0` to `0.155.1` and Claude Code `2.1.270` to `2.1.276` updates, this
decision supersedes ADR 0001's requirement to update the runner pin, provenance fixture, and
capability evidence in the same change. It preserves the rest of ADR 0001, including exact
executable verification and the requirement for an explicit decision when fixtures change.

The following evidence retains its original meaning and versions:

* `apps/stokowski/test/fixtures/runners/provenance.yaml` records the historical Codex and Claude
  versions and the resolve, probe, and reject-drift contract.
* The `codex-events`, `codex-tool-resolution`, and `claude-tool-resolution` rows in
  `apps/stokowski/test/fixtures/compatibility_ledger.yaml` identify the sources of their
  fixtures. Their source fields do not declare the current installation versions.
* `runners/codex.yaml` and `runners/codex-events.jsonl` remain the argv, session, effort, and
  event-normalization contracts owned by
  link:0003-runner-permissions-session-and-lifecycle.adoc[ADR 0003]. The fixture-backed tests
  and the temporary checkout versions in `apps/repo_management/test/mix/tasks/stokowski_test.exs`
  continue to exercise those contracts.

At launch, `Mix.Tasks.Stokowski.resolve_runner!/2` reads each configured runner's exact version
from the root `mise.toml`, resolves its absolute path with `mise which`, and probes that path
with `--version`. The observed version must match the current pin. The historical fixture is
not consulted to choose or accept an installed executable. Codex `0.154.0` and Claude Code
`2.1.270` therefore remain valid historical evidence but fail the current checkout's version
check if selected for launch.

This refresh retains the existing runner capability requirements. It does not claim that the
old event capture was produced by Codex `0.155.1`, or that new capabilities in either runner
have been characterized. Any change to argv, events, session handling, effort, permissions,
environment containment, or lifecycle behavior requires corresponding evidence and an explicit
compatibility disposition.

== Verification

Run repository checks from the umbrella root through the updated toolchain:

[source,shell]
----
mise install
mise exec -- mix setup
mise exec -- mix format --check-formatted
mise exec -- mix test
mise exec -- mix phase0.verify
----

Also call `Mix.Tasks.Stokowski.resolve_runner!/2` for both `codex` and `claude` from the umbrella
root to verify the real mise-selected executables against the current pins:

[source,shell]
----
mise exec -- mix run --no-start -e '
  for runner <- ["codex", "claude"] do
    {path, version} = Mix.Tasks.Stokowski.resolve_runner!(File.cwd!(), runner)
    IO.puts("#{runner} #{version} at #{path}")
  end
'
----

Fixture tests use controlled executables and historical events; passing them establishes
regression coverage, not a live authenticated turn on the updated runners. The version probes
establish executable identity, not protocol compatibility. The Phase 0 CI matrix continues to
own native Linux x86_64 and macOS arm64 verification under
link:0005-distribution-and-release.adoc[ADR 0005].

For the pin-update commit `0286625c7670287213025d83c2fdfc11fa087bee`,
https://github.com/rubyists/fantasia/actions/runs/35418258742[Phase 0 CI run 22] passed setup,
formatting, tests, and `phase0.verify` on both native targets. This verifies the repository
contracts under the updated toolchain within the limits above.

== Consequences

The dependency refresh can proceed with an explicit, version-scoped compatibility decision
without relabeling historical observations. Future runner updates must either supply new
provenance and capability evidence together with their pins, as ADR 0001 requires, or record a
new explicit compatibility decision. This exception does not automatically cover later versions.
